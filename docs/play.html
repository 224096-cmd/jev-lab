利用方針（必読）

運営者が公開 API として提供しログイン不要で CORS を許可している情報源だけを使う。対象は出来事・地域・話題。個人の特定・追跡・プロファイリングには使わない。取得結果は出典 URL と取得時刻つきで記録する（証跡）。レート制限（Nominatim 1 req/s、GDELT 5 s/req）を守る。

動画で紹介される「情報収集ツール」のうち、公開情報を受動的に読むだけの手法をブラウザで再現。対象はサイト・ドメイン・出来事。個人の特定・追跡には使わない。Shodan・HIBP など API キーが必要なものと、ユーザー名の横断照会（個人対象）は実装しない。

① 検索演算子（dork）ビルダー

Google 等の検索演算子で「公開されている文書」を狙って探す。URL を組み立てて開くだけで、自動巡回はしない。

② ドメインの素性（DNS・WHOIS/RDAP・Wayback・証明書ログ）

「そのサイトはいつからあるか／誰が運用しているか／どんなホストがあるか」。結果は根拠として情報収集に渡せる。

③ 画像のメタデータ（EXIF / GPS）

自分の端末で選んだ画像を端末内で読む（送信しない）。SNS 経由の画像は通常メタデータが消えている＝「消えていないなら一次投稿の可能性」という手がかり。

④ 逆画像検索・横断検索リンク

画像 URL やキーワードを各サービスで開く。使い回し画像（別の災害・別の年の写真）の発見に。

使えるモデル

Hugging Face で Jev 級モデルを探す

HF API（公開）。transformers.js / onnx タグがあるものはブラウザ実行の候補。それ以外は PC（config/models.yaml）用

Hugging Face のモデルを追加（コピペ）

Transformers.js 対応（ONNX 同梱）のリポを指定。hf-zeroshot は NLI 系（zero-shot-classification）、hf-embed は文埋め込み（feature-extraction）。追加後は上のモデル欄に出る。PC 専用（GLiNER2 / open-jev / LLM）は config/models.yaml。

対応する kind：open-jev-onnx（open-jev 形の Transformers.js 版。入力 input_ids/attention_mask/seg/pair_q/pair_opt）、crossenc（日本語 Jev cross-encoder。PC で export_crossenc.py --hf 〈id〉 --name 〈name〉 を実行して docs/models/ に置き、push してから登録）。Jev 級でないモデル（NLI・埋め込み・LLM）はこのラボの比較対象にしない。

例（コピペ用）
{ "name": "open_jev_deberta_v3_large", "kind": "open-jev-onnx", "hf_id": "onnx-community/open-jev-deberta-v3-large-ONNX", "dtype": "q4", "dtype_webgpu": "q4f16", "temperature": 1.05, "language": "en" }
{ "name": "jev_ja_310m_argos", "kind": "crossenc", "language": "ja" }   ← docs/models/jev_ja_310m_argos/ を export_crossenc.py で作った場合（index.json に自動登録される）
