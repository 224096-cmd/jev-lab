0. 何を解く問題か

大量の文章（投稿・報道・公式発表・回答）を決められた観点で素早く、安定して、確率つきで仕分けたい。LLM に「JSON で答えて」と頼む方法は、出力形式が崩れる・同じ入力でも答えが揺れる・遅い・大きい、という問題がある。Jev 級モデル（typed-decision model）は生成をやめ、「状況 + 型付き質問 → 確率分布」だけを 1 回の forward で返す設計で、この問題を解く。

例：投稿「【拡散希望】○○小学校が津波で水没！」に対し、
種類 ∈ {公的発表, 報道, 目撃, 意見, 無関係}、緊急度 ∈ {0..5}、拡散依頼あり? ∈ {yes,no}、根拠と整合? ∈ {yes,no} を同時に答える。

1. 型付き判断（Jev の形）

状況 s（本文＋根拠）と N 個の質問 qj = (質問文, 選択肢集合 Oj)。出力は各質問について選択肢上の確率分布 pj（Δ は確率単体）。3 つの型はすべて「1 つの softmax」に帰着する：

型選択肢読み出し用途
Choice任意の K 個（最大 255）argmax分類・振り分け・意図
Score順序つき段階 ℓ1<…<ℓK期待値 Σ pkℓk緊急度・感情強度・類似度
Noul{yes, no}p(yes)該当判定・整合性・要対応

構造化出力エラーは構造的に 0（生成しないため）。1 状況に N 質問を載せても forward は 1 回。

2. トークン化と入力列

特殊トークン [STATE] [Q] [OPT] を語彙に追加し、状況・質問文・各選択肢を 1 本の列に並べる。トークナイザは SentencePiece Unigram（語彙 10 万）。語彙に無い文字は UTF-8 の byte fallback（<0x0A> など）に落とす。ブラウザ側（Transformers.js）はこれを実装していないため、本ラボでは JS で再現し、Python と完全一致させた（Play の「仕組み・可視化」で確認できる）。

各スパン（質問文 j、選択肢 (j,k)）のトークン位置 [s,e) を記録しておく。これが読み出しの鍵。

3. エンコーダ（自己注意）

ModernBERT-Ja（30M/70M）は双方向 Transformer。各層で全トークンが互いを参照する（自己注意）ので、選択肢トークンの表現には状況と質問文の情報が混ざる。ここが「選択肢を別々に埋め込んで比較する」方式（bi-encoder）との決定的な違いで、cross-encoder として働く。出力 H ∈ ℝL×d（d=256 for 30m）。

4. 読み出し（プーリング）

span：質問文トークンの平均 uj、選択肢トークンの平均 vjk。marker：[OPT] マーカー位置の 1 ベクトル。英語の再現実験（Kotoba typed-decisions）では marker 読み出しは事前学習で意味を持たない新規トークンのため学習が進まず、span が有効だった。本ラボでは同じ forward から両方を計算し、切替で差を見られる。

5. 判断ヘッド

入力は [u ; v ; u⊙v]（連結・要素積）。u⊙v は内積の分解で「どの次元が一致しているか」を明示し、小さい MLP でも類似度以上の関係（否定・順序・部分一致）を学べる。パラメータ数 ≈ 3d·512 + 512 ≈ 39 万（30m の場合）。ヘッドだけの学習（--freeze-backbone）は数十秒で終わり教材デモに向く。全体微調整はエンコーダも更新する。

6. softmax と温度

T<1 で分布は尖り、T>1 で平らになる。argmax は T で変わらない（順序保存）。変わるのは「確信度」だけ。下のスライダで体感できる。

T = 1.00

z = [1.2, 0.4, −0.3, 0.9] を固定して T を変えたときの softmax。

7. Score・Noul の読み方

Score は段階を数値 ℓk（既定 0..K−1）とみなした期待値。argmax でなく期待値を使うので「1.035」のように段階の間に落ちる。段階が未見の言い換え（例「高い→大きい」）に変わると壊れやすいことが英語で報告されており、OOD 評価の対象。Noul は p(yes) を閾値 0.5 で判定するが、閾値は用途で変える（見逃しを減らしたいなら下げる）。

8. 損失：CE と Brier

CE（対数損失）は正解確率を上げる力が強いが、過信（確信度＞正解率）を生みやすい。Brier（二乗誤差）は分布全体の形を正解 one-hot に近づけ、較正を助ける。両方の和で学習し、λ は実験パラメータ（--brier）。下図は正解確率 p に対する 2 つの損失。

9. 較正：ECE と温度スケーリング

「確信度 80% と言った判断が実際に 80% 当たっているか」を測る。信頼度を 10 等幅ビンに分け、ビンごとの |正解率 − 平均確信度| を件数で重みづけした和が ECE。空ビンは除外し補間しない。温度スケーリングは検証データで NLL を最小にする T を 1 つ選ぶ事後補正で、精度を変えずに ECE を下げる。Play のバッチ評価が較正表と信頼性図を出す。

10. ゼロショット cos との関係

ヘッドを使わず cos(u, v) に定数 s を掛けて softmax すると、学習なしの判断器になる（Play の「手法: cos」）。エンコーダは選択肢と状況を同時に読んでいるので、bi-encoder の類似度より情報が多い。学習したヘッドとの差 = 「ヘッドが cos 以上に学んだ関係」。未学習モデルでは cos の方が意味のある答えを出す。

12. 評価の 5 軸と OOD

Smart（精度・MAE）／Cheap（サイズ・単価）／Fast（p50/p95）／Reliable（Brier・ECE・有効回答率・言い換え一貫性）／Open（重み・コード）。合成スコアは作らない（トレードオフを見せるのが目的）。

OOD 分割：test と同じ state に、未見の質問文（言い換え）や否定形（gold 反転）を付けたもの。in-domain で高く OOD で低いなら「質問を読まずに slot を暗記した」。Play の検証タブ②③はこれを 1 件で試す簡易版。

13. 量子化と端末実行

エンコーダの重みを int8 に動的量子化（155 MB → 37 MB）。行列積は int8、それ以外は fp32。隠れ状態の cos 類似は fp32 比 0.993。判断（argmax）がどれだけ変わるかは実験項目（fp32 版と比較）。ブラウザでは ONNX Runtime Web（WASM、対応端末は WebGPU）で実行し、モデルは IndexedDB に保存して機内モードでも動く。

14. 情報収集への適用（このラボのメイン）

「調べたいこと」→ 公開 API（気象庁・Wikipedia・Wikidata・OSM・Bluesky・GDELT）から収集 → 各情報に型付き質問（関連・種類・緊急度・具体性・拡散依頼・根拠との整合）→ 説明できる信頼性スコア = Σ wk fk / Σ wk（重みは編集可）→ 類似投稿のクラスタ化（コピペ検出）→ 地理照合（地名→座標→標高）→ 証跡保存 → 人手ラベルで自分のデータセットを育てる。

JEV が担うのは「判断」だけで、収集・照合・スコア合成はルールと公開データが担う。LLM は使わない（使うなら比較対象として）。これが「小さく・速く・説明できる・オフラインで動く」情報整理の設計。
